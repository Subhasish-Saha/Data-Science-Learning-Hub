⚠ Library currency — verified August 2026

Two answers in this subject changed in 2026, which makes them useful differentiators:

  • pandas 3.0 (21 Jan 2026) made Copy-on-Write the only mode, which removed SettingWithCopyWarning entirely and turned chained assignment from unpredictable into reliably silent. It also changed the default string dtype from object to str — so select_dtypes("object") no longer finds string columns — and defaulted datetimes to microsecond resolution. Covered in §7.3 and §7.5.
  • Python 3.14 made free-threaded builds officially supported (PEP 779), so “the GIL means Python can't do parallelism” is now doubly wrong. Covered in §9.6.
  • Also current: NumPy 2.5 (dropped Python 3.11, improved free-threading), scikit-learn 1.9.

Any tutorial that tells you to fix SettingWithCopyWarning with .copy(), or that object dtype means “string”, is describing pandas 2.x. Cross-check against pandas.pydata.org.
